## 4. The ocean — the biggest open item

**The spectral ocean has never rendered, since Phase 5. The sea in every capture
and in the running game is the terrain bed wearing water shading.** Disabling the
ocean mesh leaves the sea visually unchanged.

**This is the parent of three of Jason's complaints**: the "corduroy" water
texture at 1 m (that is terrain meso-detail), the land/water boundaries, and
probably some of the colour slashes.

### Proven

- **The vertex, matrix and shading path is perfect.** A synthetic in-vertex
  displacement renders clean parallel wave ridges.
- **`clamp(displacement, ±3 m)` in the vertex RENDERS real irregular spectral
  wave structure.** The field has valid content.
- **The algorithm is correct.** The existing CPU harness (`runFftChain` from
  `tests/render.webgpu-ocean-fp16.test.ts`, in Float64) run at the **real shipping
  config** — res 128 and 256, depth 2000, seed `0x4f434541`, all five cascades —
  gives peak heights **0.15–3.0 m** and max stage magnitude **0.4–71** against an
  f16 ceiling of 65504. **Zero overflow.**

### Eliminated, each by measurement or by reading

| Hypothesis | How it died |
|---|---|
| Missing 1/N² normalisation | Four independent scalings, none renders |
| f16 intermediate overflow | Harness at shipping config: max 71 vs 65504 |
| JONSWAP spectrum singularity | Same harness run; spectrum is sane |
| Separate per-stage uniform buffers | Babylon builds ONE shared LeftOver UBO |
| Uniform declaration-order divergence | Reordered both to identical prefix; no change |
| Missing barriers between FFT dispatches | Each stage is its **own compute pass** |
| Dispatch coverage | Half-res dispatch writes **both** butterfly outputs |
| FFT `params` layout mismatch | WGSL and CPU offsets match |

### ROOT CAUSE — FOUND

**Cascade 3's displacement texture is 100% NaN. The ocean vertex sums all five
cascades, so one poisoned cascade makes every vertex NaN and the whole mesh
collapses to nothing.** It was never huge, and never flat — it was NaN.

**Measured by a device-level `copyTextureToBuffer` readback, reading raw f16/f32
texels straight off the GPU:**

```
ocean-displacement-0/1/2   finite
ocean-displacement-3       65536 / 65536 NaN

ocean-h0-3  (initial spectrum, f32)   60 Inf texels
ocean-a0-3  (first transform, f16)    fully NaN
ocean-b0-3                            half NaN
```

**A handful of Inf in the initial spectrum; the FFT butterfly computes
`Inf − Inf = NaN` and spreads it across the entire field.**

**The instrument carries its own control: identical code returns FINITE for
cascades 0–2 and NaN for cascade 3, so it can return both answers.**

### The two things this reconciles

**Why the f64 harness said "all sane": an f64 oracle is structurally blind to f32
Inf.** It carries the same texel as a large finite number and reports a sane peak
height. That is why it green-lit all five cascades.

**Why `clamp(±3 m)` rendered:** it did **not** bound huge values — **it
neutralised the NaN.** WGSL `min`/`max(NaN, guard)` returns the guard, which is
this codebase's own recorded `tanh` trap. The NaN cascade went quiet and the four
finite cascades' real structure showed through. **Two facts that had no common
explanation, one mechanism.**

### The fix

**A non-finite guard on `h0` at the end of initialisation** — store 0 when
`!isFinite`, or clamp `h0` to a finite bound. **That kills the Inf at source
before the FFT can spread it.** Minutes to add, then confirm by capture.

**The exact line writing the 60 Inf into `h0-3` was not pinned.** The three
obvious suspects are all already guarded — the Gaussian's `u1` has
`max(…, 1e-7)`, `tanh` feeds `max(…, 0)`, and the analytic spectrum is bounded
around 400 — **so the Inf enters by a path the current guards miss, specific to
cascade 3 (patch 4096, depth 2000). The guard is correct regardless of which
expression produced it.**

**Write the NaN-laundering trap into the fix's comment.** `clamp(NaN, a, b)`
returns `a`, so **any future defensive clamp in this shader can silently hide a
NaN and look like it fixed something.** That trap cost the most tonight.

### Independently actionable, do not wait for the fix

**`tests/render.webgpu-ocean-fp16.test.ts` validates res 256 / depth 900 / seed
`0x5eed`. Shipping tier 1 is res 128 / depth 2000 / seed `0x4f434541`.** The one
test that exists to validate this subsystem **has never exercised the shipping
config.**

**And it must assert FINITENESS and an upper bound, not just a floor** — a
floor-only guard would have stayed green through this exact bug, and an f64
harness cannot see f32 Inf at all.

### Related and already landed

**`7b2d08b`** fixes `BathymetryClipmap` sampling the bed at dispatch-local
coordinates instead of world. **It is invisible today because its consumer is the
ocean shader — and it becomes visible and correct the moment the ocean renders**,
because it is what makes near-shore depth right. **Expect near-shore shading to
change when the ocean fix lands.**

## 7. Traps — these each cost an hour or more today

**A baseline captured before someone else's commit is not a baseline.** One arm
was 45 minutes stale with two ground commits in between; the contaminated answer
was −3.5% and the clean one **0.0%**. **The contamination was the entire signal.**
On a fleet landing commits every few minutes, "captured earlier today" is stale
by default.

**Never magnify with `kernel: "nearest"`.** It amplified near-Nyquist **7×** and
manufactured a "1.5–2 px cross-hatch" that steered four hours of work. **Native
pixels only, both arms, no JPEG.**

**Check your crop is bigger than the feature.** A 380 px window on a 1280 px frame
held ~3 blobs of a 60–130 px pattern. **That is a background, not a pattern** —
and it cost more than the artefact did.

**An A/A control proves reproducibility, not validity.** A deterministic pipeline
reproduces an analysis artefact as faithfully as a real feature. **It licenses
A/B; it does not license "my detector found a thing and the thing reproduces."**

**A clamp can launder a NaN and look like it fixed something.** WGSL
`min`/`max`/`clamp(NaN, guard)` returns the guard. A `clamp(±3 m)` on the ocean
displacement was read all evening as "the values are huge and clamping bounds
them"; it was actually neutralising a NaN. **The whole "huge displacement"
framing was an inference from a clamp appearing to work.**

**A clamped output cannot exonerate its input.** `slope_foam` is clamped to ±8, so
it looked sane while the unclamped displacement beside it was NaN.

**An f64 oracle is structurally blind to f32 Inf and NaN.** It carries the same
texel as a large finite number and reports a healthy peak. **The ocean bug hid
behind this for the entire evening.**

**`readPixels` is unreliable on rgba16float/rgba32float storage textures** — it
returned max=1 on displacement and 0 on the spectrum, which cannot both be true.
**Use a device-level `copyTextureToBuffer` + `mapAsync` instead; that is what
found the fault.**

**An instrumentation varying can be overwritten by the shader's own code.** One
probe assigned to `vertexOutputs.waveCrest` and the shader overwrote it two lines
later; every reading was of something else. **Write instrumentation varyings
last.**

**A parameter sweep over an input space is not a sample of the world.** Three
separate fixes today were validated over conditions the world never generates.
**Measure the realised distribution.**

**A number can be right and could not have been otherwise.** One sweep supplied no
`canopyClosure`, so a default left `ForestFloor` at full strength in every probe
— the answer was guaranteed by its own configuration, and no control catches that
because the control shares it.

**"grep finds no branch" is a search result. "No branch implements it" is a fact
about the code.** A case-sensitive search missed a mode whose name appears once,
capitalised, in a comment.

**A control satisfied in every candidate cannot discriminate between them.**

**A guard that scans for a symbol tests that somebody typed the word.** Extract
the behaviour and call it.

**Sweep the estimator's own parameters** — kernel, window, fit order. Levels moved
44% across kernels; ratios held, **except where an endpoint approaches zero**.

**Check both pre-registered branches predict different measurements.** One arm was
wasted because both branches predicted the same thing.

**Run controls in a separate worktree**, never by stashing a shared checkout. Seven
sessions read this tree.

**Hand work over as a patch FILE.** The tree is not a handover medium here.

**`| head` eats the exit status**, and `$?` is `head`'s. **Timing verdicts on this
host are not actionable**; the pixel channel is fine.
